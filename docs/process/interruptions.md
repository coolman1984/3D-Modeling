# Documentation, logs and interruptions

How the project keeps its own record, so that a session that stops halfway (a crash, a usage
limit, a closed terminal, a lost chat) never loses work or the knowledge of where it stood.
Decision 0017 explains why it works this way.

## What lives where

| Record | File | Written by | Changes |
|---|---|---|---|
| Finish line and checklist of the current stage | `TASKS.md` | people and agents, by hand | tick items as they are done |
| Where work stands right now | `docs/STATUS.md` | `pnpm docs` (generated) | every run |
| Project history, one entry per commit | `docs/CHANGELOG.md` | `pnpm docs` (generated from git) | every commit |
| Index of all documents and decisions | `docs/README.md` | `pnpm docs` (generated) | when docs are added |
| Work log: checkpoints and notes, newest last | `docs/log/YYYY-MM.md` | `pnpm checkpoint`, `pnpm log` | append-only |
| Snapshots of unfinished work | git ref `refs/checkpoints/<branch>` | `pnpm checkpoint` | every checkpoint |
| Why things are the way they are | `docs/decisions/NNNN-*.md` | by hand | one per decision |
| Plans | `docs/0*-plan.md` | by hand | rarely |

Generated files start with a "Generated by scripts/docs.mjs" comment. Never edit them by hand; edit
their source (`TASKS.md`, commit messages, the docs themselves) and run `pnpm docs`.

## Commands

```bash
pnpm checkpoint "what I was doing"   # snapshot the working tree, log it, refresh generated docs
pnpm checkpoint --push "…"           # same, and copy the snapshot to GitHub (off this machine)
pnpm log "found X, next Y"           # add a note to the work log, refresh generated docs
pnpm docs                            # refresh generated docs only
git log refs/checkpoints/<branch>    # list the snapshots of a branch
```

A checkpoint never touches the branch, the staged files or any working file. It records a normal
git commit whose parents are the previous checkpoint and the current HEAD, so it is a complete,
restorable copy of every tracked and new (non-ignored) file. Changes that touch only the generated
files do not make a new checkpoint.

## Working rhythm (agents and people)

1. Start of a session: read `docs/STATUS.md`, then the `## Now` section of `TASKS.md`.
2. Before a long or risky step (a big refactor, a long test run, a dependency change) and after
   each finished checklist item: `pnpm checkpoint "<item>"`.
3. When something surprising is found: `pnpm log "<finding>"` and add it under "Found along the
   way" in `TASKS.md`.
4. End of a stage: commit (the changelog picks the message up), `pnpm docs`, push.

## After an interruption

1. `pnpm docs`, then read `docs/STATUS.md`: branch, open items, uncommitted files, last checkpoints.
2. Nothing is lost if the files are still on disk; carry on from the first open item.
3. If files were lost or damaged (a bad checkout, `git clean`, a broken edit):
   - see what a snapshot holds: `git show --stat refs/checkpoints/<branch>`
   - compare it with now: `git diff refs/checkpoints/<branch>`
   - restore everything from it: `git checkout refs/checkpoints/<branch> -- .`
   - or one file: `git checkout refs/checkpoints/<branch> -- path/to/file`
   - an older snapshot: `git log refs/checkpoints/<branch>` and use its hash instead.
4. Run `pnpm typecheck` to see what the interrupted work left half-done.

## Making it automatic

Checkpoints are most useful when nobody has to remember them. Two optional switches, each turned on
once per machine by the owner (they change local tool settings, so an agent does not turn them on):

**Claude Code hooks** (a checkpoint at the end of every agent turn and before the chat is
summarised). Add to `.claude/settings.json`:

```json
{
  "hooks": {
    "Stop": [{ "hooks": [{ "type": "command", "command": "node scripts/checkpoint.mjs --quiet \"end of agent turn\"" }] }],
    "PreCompact": [{ "hooks": [{ "type": "command", "command": "node scripts/checkpoint.mjs --quiet \"before context summary\"" }] }]
  }
}
```

**Git hooks** (refresh the changelog and status after every commit):

```bash
git config core.hooksPath .githooks
```
